# 开源维护基线记录

日期：2026-10-15。当前为 Unreleased，未发布稳定版。

下表保留初始基线的历史边界。现行多发送端、资源预算及远程参数扩展以 PROTOCOL.md 和 [授权模型](ACCESS_CONTROL.md) 为准；远程参数修改已改为显式能力声明、逐条授权校验及 Local 实际执行，不沿用旧 inline config。

## 原始问题与处理

| 原始问题 | 本轮处理 | 当前边界 |
|---|---|---|
| README 宣称远程参数配置，代码丢弃 config | 去掉无效控件并显式拒绝旧 config | 参数由 Local 设置，远程修改另行设计 |
| 多 Remote 接收只转发给第一个匹配连接 | 按 Local/portId 向全部订阅者转发 | 多端都可写，尚无仲裁 |
| 注册、映射、队列跨协程修改，通道可能被重复关闭 | Hub 单事件循环拥有所有状态和发送通道生命周期 | 每个连接保留独立读写泵 |
| 校验串口前已建立映射和队列 | 先验证再建立订阅，重复连接幂等 | 连接确认仍不是物理写入 ACK |
| 串口关闭、Local 离线和网络重连遗留状态 | unregister/local_disconnected、重注册、Remote 状态复位 | 不缓存断网数据、不自动恢复 Remote 订阅 |
| 可提供其他连接 ID、消息角色未约束 | 发送身份从连接取得，校验角色与 portId | 五位 ID 仍不提供认证 |
| 不限帧、无心跳、发送积压时静默丢消息 | 帧限制、心跳、读写超时、慢客户端断开 | 未实现全局连接/速率限制 |
| HEX 非法输入、CR/预设命令不正确、模式切换重复累积 | 严格字节转换、真实 CR、保留记录重绘、流式 UTF-8 | 显示与导出只保留有限记录 |
| 私钥/证书/二进制被跟踪，无维护约束和回归基线 | 移至 .local/legacy，MIT、文档、测试和 CI 配置 | 历史仍有旧私钥，不重写历史 |

## 后续补充：网络参考失败诊断

2026-10-16，用户反馈 6 次探测全部失败，其中 5 次超时。服务器上的采样接口响应正常，但现有证据不足以确定该轮客户端失败的实际原因。回归测试确认：旧版 1.5 秒上限会把 2 秒响应的可用连接全部计为失败；现将轻量探测改为 5 秒、下载样本改为 10 秒，页面分别显示超时、HTTP 状态、网络连接和响应内容错误。保留无有效样本时不给出波特率的规则。

Go 格式检查、vet、全量 Go 测试、61 项 Node 测试及 94/94 变异通过。真实 Chromium 在本机 HTTPS 服务验证两侧正常评估、取消、波特率不变，以及 HTTP 401、浏览器离线时的具体错误和窄屏显示。此次未在公网点击评估，未重测真实串口；这些检查不能证明用户链路故障已恢复。

## 后续补充：多发送端与统一队列（v3）

2026-10-16，用户明确“同一时间一方发送”指实际写入统一排队，多个 Remote 可同时获批发送。本轮取消持续独占发送端，Local 始终可发送；暂停保留 Remote 订阅和 RX，关闭自动接受，恢复等待确认并丢弃旧队列。每次授权与写入状态使用新代次，防止撤销/重批或暂停/恢复后的旧命令复活。Local TX 记录来源与入队序号，Remote TX 明确表示提交。

Go 全量测试、vet、格式检查、WSL/Linux race、70 项 Node 测试及最终完整 119/119 变异通过。真实 Go WebSocket 并发测试验证两个发送端与暂停协议；本机真实 Chromium 使用模拟串口验证两个发送端和 Local 同队列、峰值一次 write、二进制保真、暂停保留 RX、旧队列不重放、撤销一个不影响其他端和窄屏布局。物理串口、设备事务与长期压力验收未在本轮重测。

实现提交 `01bc95e` 已部署，公网匿名 HTTP/HTTPS/WSS 与全新 Chromium 复核通过，模拟串口实际 write 峰值为 1。页面和资源返回 200、零字节健康检查 204，版本头正确；代理来源校验与免登录入口保持。没有进行公网带宽评估或真实硬件压测，旧页面须同步刷新为 v3 再重新授权。
