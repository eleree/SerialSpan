# Remote ESP32-C3/S3 串口烧录

## 范围

工具运行在 Remote 页，通过共享码连接到 Local 打开的串口（例如 Local 主机上的 COM7）。芯片检测、复位、参数切换和固件字节都经获批的 Remote WebSocket 串口链路到达 Local；浏览 Remote 页的电脑不需要直连 ESP32 USB。BIN 文件由 Remote 浏览器读取、校验写入范围并计算摘要，固件字节以普通有界串口数据帧经服务转发，不作为文件保存到服务器。

需要 Local 和服务端支持 `flashProtocol=1`、串口参数修改及 DTR/RTS 控制信号。Remote 必须申请完全控制并经 Local 批准；默认只读连接不可烧录。烧录会话暂时独占该串口的写入，Local 与其他 Remote 的普通发送和参数修改停用，接收仍可用。Local 暂停远端操作、撤销授权或断开会释放会话；会话还需要周期续期，失去续期会超时释放。Local 页面不提供烧录入口，只显示占用状态。

首期支持 ESP32-C3 和 ESP32-S3 UART ROM Bootloader；工具使用 115200 baud 执行芯片检测与烧录，并将 SLIP 帧控制在服务端 16 KiB 数据上限内。正常结束时会尝试恢复 Local 原波特率；若浏览器或网络在清理前中断，Local 可能保留最后一次已确认的波特率，可在 Local 参数栏核对并调整。它不是 Wi-Fi OTA，也不提供整片擦除或 eFuse 写入。2026-10-22 已在 COM7（ESP32-S3 QFN56 revision v0.2、8 MB Flash）上通过 Remote 实测芯片检测、IDF 5.3.2 Hello World 三镜像烧录、三镜像 `esptool verify_flash` 和 Local RX 启动输出；设备 Secure Boot 与 Flash Encryption 均为关闭。此结果只覆盖这一块板、这一驱动与这一固件包，不替代 ESP32-C3、掉电/断网恢复和其他 USB 串口驱动的验收。

## 固件包

远程协议包读取至少等待 30 秒，保留烧录库本来更长的擦除/写入超时，收到完整回复后立即继续。这样可兼容超过直连 USB 100 ms 同步等待的网络往返延迟；网络中断或超时仍会报错，连接断开后不会自动重连继续烧录。

压缩数据按 2 KiB 分块，等待当前设备回复后再发送下一块；浏览器 WebSocket 发送积压超过 64 KiB 时停止提交新帧。Remote 每 7 秒续期，会话 90 秒未续期释放；WebSocket 仍保留 25 秒 Ping、60 秒读超时和 10 秒写超时，因此 90 秒不是断网后继续写入的保证。暂停、撤销与断开仍立即作废旧排队项，不能跨会话续传烧录命令。

页面只提供 BIN 文件与写入地址，不需要 JSON 清单。默认显示 8 行，可点击每行的 `…` 独立选择文件，或批量选择；先填写的地址会保留。文件列表是主体，SPI 参数及设备信息放在右侧，开始/停止、进度与深色日志位于下方。共享码顶栏及 Remote 工具侧栏保留，控件与配色沿用 Local/Remote 样式；窄屏时纵向排列。

勾选需要烧录的行，填写 `0x` 开头、按 4 KiB 对齐的地址，选择 DIO/QIO/DOUT/QOUT 与 20/40/80 MHz。目标芯片及容量以实际检测为准。地址须使用该次构建输出的偏移，不能从文件名猜测；合并 BIN 只需选择一行，写入地址以合并时指定的起始地址为准。

工具检查文件名、空文件、32 MiB 总大小上限、地址重叠和 Flash 越界，并计算 SHA-256 供核对。摘要不证明发布者身份，也不保证文件适合该板卡。未连接时可先选择文件和填写地址；校验与开始烧录仍要求已获完全控制、已检测的当前串口会话。

文件、勾选项、地址或 Flash 参数变化后，旧校验结果与确认立即失效；校验期间表单或会话若已变化，迟到结果不会重新启用烧录。

## 烧录与恢复

1. 在 Remote 顶部输入 Local 的共享码，申请完全控制并等待 Local 批准。Local 应先打开目标 ESP32 所在的串口并启用共享。
2. 打开 Remote 左侧的 **ESP32 烧录**。点击“连接并检测”后先按需加载本地托管的烧录库，最多等待 180 秒，准备期间尚不占用串口。加载失败后可检查网络并重试；“停止”会取消本次操作，迟到的加载结果不会申请串口锁。准备完成后 Remote 请求独占串口会话，通过 DTR/RTS 复位与读取芯片信息；Local 本机和其他 Remote 此时不能发送数据。
3. 选择 `.bin` 并逐行填写地址；勾选本轮要写入的镜像，执行校验并核对摘要中的每个偏移与文件大小。
4. 勾选确认后开始写入。默认不整片擦除，不操作 eFuse；写入成功后请求远程硬复位并尝试恢复 Local 原波特率。
5. 主动结束会话、暂停远端操作、撤销授权或断开连接都会释放串口锁。断线或写入失败时，设备可能仍停在 Bootloader；按板卡说明重新进入下载模式后再连接和烧录。

下载区的“停止”复用 Remote 断开流程，忙时仍可操作，立即作废当前远端授权与会话并中止后续发送；再次操作需要重新申请。它不会关闭 Local 持有的物理串口，也不保证已写入部分可以回滚。

写入进度按每个 BIN 的原始大小加权计算该镜像的压缩传输比例，写入阶段最高显示 99%。只有写入、设备复位、原波特率恢复和串口锁释放均成功后才显示 100% 与完成提示；进度不代表设备已经正常运行，启动结果仍需核对串口输出。收尾失败会单独报错，不能视作完整升级成功。

升级期间不能保证串口写入可回滚。电源、USB 或网络在写入过程中断开，设备可能需要重新进入下载模式，并用同一份经过核验的完整镜像包修复。已启用 Secure Boot 或 Flash Encryption 的设备可能只接受正确签名或加密的镜像；本工具不配置安全熔丝或生成安全密钥，未知安全状态的设备不得尝试烧录。

## 与 OTA 的边界

串口 ROM Bootloader 烧录由 Remote 通过 Local 的物理串口完成。Wi-Fi OTA 则要求设备固件已经实现 OTA 客户端和兼容的分区布局。ESP-IDF OTA 通常需要 `ota_0`、`ota_1` 应用槽和 OTA data 分区，并需要设备端决定新固件何时通过健康检查和回退。OTA 发布、签名、设备身份、下载授权和服务端资源预算均未包含在本工具中。

## 第三方实现

浏览器 ROM Bootloader 协议使用 Espressif [`esptool-js`](https://github.com/espressif/esptool-js) 的本地打包版本；依赖版本、SHA-256、许可证和更新方式见 [第三方声明](THIRD_PARTY_NOTICES.md)。此工具不编译 ELF，也不替代 ESP-IDF 构建流程。偏移应以 [esptool 烧录文档](https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/flashing-firmware.html)和对应项目实际构建输出为准；OTA 分区要求见 [ESP-IDF OTA 文档](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/system/ota.html)。
