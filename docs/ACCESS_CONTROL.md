# 共享授权与串口写队列

当前协议为 v3。每个 Local 操作一个物理串口，决定 Remote 权限。`read` 为只读，可接收和查看已确认参数；`control` 为完全控制，可发送，并在 Local 声明 configProtocol=1 时申请修改参数。控制权限不独占，可以同时批准多个端。

## 授权

- Remote 默认申请只读。批准前不返回串口详情或数据，Local 可以批准、降为只读、拒绝或撤销。
- 每 Local 最多 8 个待批准请求、16 个已授权 Remote。请求 60 秒过期，128 位随机 requestId 绑定实际连接与一次决定。
- 每次批准生成新的 grantId（取该次 requestId）。它只标识一次授权代次，不能替代连接身份；服务器仍从 Socket 确定发送方。
- 自动接受默认关闭，显式开启后可以批准多个只读和发送端。本机写入或已有发送端不会阻止新的发送授权。开启偏好保存在 Local 浏览器，仅共享注册后生效。

## 统一排队

Local 的本机发送和所有获批发送端共用一个 FIFO，最多 256 项，每项最多 16 KiB。顺序按 Local 的入队先后确定，不按远端时钟排序；同一时间只调用一次串口 write，单次发送的字节不与其他发送交叉。

服务器逐条检查发送权限、端口、grantId 和 writeEpoch。Local 在入队及执行前再次检查当前授权与发送状态；撤销后重新批准同一 Remote ID，旧授权的排队命令仍不能执行。

串口 P2P 使用相同规则：服务器逐条校验 TX 意图，将序号、长度、SHA-256 与当前授权/代次绑定为许可；Local 仅将摘要匹配的直连字节交给原写队列，摘要计算后及实际写入前均复核。直连中断不重发旧 TX。RX 可以直连，但仍使用原流和序号缓存，缺帧由获批连接通过 WSS 补收；暂停不影响接收和补收。具体消息见 PROTOCOL.md。

队列保证写入顺序，不提供设备协议的事务隔离或应答匹配。RX 仍广播给所有获批 Remote，无法通用地认定某段响应属于哪次命令。驱动 write 成功也不代表设备已执行，失败可能仍有在途字节；不自动重试。

ESP32 ROM 烧录是有界例外：获批的完全控制 Remote 可申请一个独占串口会话，防止其他端的字节插入 Bootloader 命令流。会话期间本机和其他 Remote 的写入被停用，RX 仍广播；会话所有者只能使用 `flash_send` 和绑定该会话的串口参数/控制信号操作。Local 暂停、撤销、断线或会话超时会释放锁，并作废旧队列项。它使用相同 Local 写队列和写入前授权复核，不提供多发送方烧录交错。

## 暂停与恢复

Local 可以一键暂停所有远端操作，保留连接、授权与接收能力；非参数切换阶段本机仍可发送。暂停同时关闭自动接受。暂停立即在本机生效，服务器确认后通知所有获批 Remote。

暂停也禁止远程修改参数并取消修改的后续步骤；参数正在切换时，本机与远端均暂停新发送，恢复须等配置状态确定。

每次状态请求递增 writeEpoch。恢复要等服务器确认，远端随后收到新状态才启用发送。暂停前未执行的远端队列项作废，恢复后不重放；已交给驱动的在途字节无法撤回。需要发送时由使用者重新提交。

短暂网络重连保留 Local 的暂停意图，但清理所有请求和授权；Remote 自动重连时必须重新申请，不能继承 grant。停止共享、关闭串口或刷新页面会清理会话；自动接受偏好保存在本地浏览器并在后续共享注册后生效。暂停、撤销控制端或资源限制停用共享会清除该偏好。单独撤销一个 Remote 不影响其他端。

## 串口参数修改

完全控制的审批包含五项受支持参数的修改，自动接受控制申请会授予相同能力。设备选择、权限对话框和实际串口 API 始终在 Local；不提供远程更换设备或打开任意串口的能力。旧 Local 未声明扩展时不能远程修改。

一次一个请求，不排队。服务器校验真实连接、订阅端口、grantId、writeEpoch 和参数代次，Local 在实际硬件步骤前后再次校验。写队列未空则拒绝修改；开始及完成均提升写入代次，旧指令不重放。只在 Local 实际确认后更新参数代次，并同步到所有获批端。

修改需停止读取、释放流锁、关闭并重新打开原设备，API 限制见 [Chrome Web Serial 指南](https://developer.chrome.com/docs/capabilities/serial)。失败尝试恢复原参数；无法确认或 30 秒超时则停止共享。暂停、撤销、断线会阻止后续步骤并尽量回退，但不能撤回已经开始的驱动调用。若物理应用已经完成，最终参数可能已变更，不能据此恢复授权。协议字段和支持值见 PROTOCOL.md；设备缓冲丢弃、复位和驱动支持须做硬件验证。

## 日志与边界

Local 已完成的 TX 记录保留本页递增的入队序号及本机/Remote 来源，导出同样保留。作废的排队命令记录跳过原因。序号可能因取消而有间隔；清空显示不会重置序号。Remote 的 TX 表示已提交，执行顺序以 Local 日志为准。

v3 必须同时更新服务端与两侧页面。旧版本在注册/申请阶段收到 protocol_mismatch，不能获得 v3 权限。没有账户身份认证；中转 TLS 在服务器终止，P2P 协商及授权也依赖受信服务器，直连不改变人员身份边界。资源限额见 RESOURCE_LIMITS.md，真实硬件验收见 ROADMAP.md。
