# 串口助手需求

更新日期：2026-10-29。需求已确定，开发与验收进度见 [ROADMAP.md](../ROADMAP.md)。

## Local 串口调试助手

1. Local 可以直接操作本机串口，包括设置参数、打开/关闭、发送和接收数据。
2. 没有远端连接时，Local 就是一个正常的串口调试助手。
3. 串口收发作为界面主体，只显示 RX/TX；连接和 P2P 等诊断不占用串口日志区域，保存在有界系统日志中并可按需导出。
4. “待批准的连接”和“已授权的远程端”放到侧边栏。
5. 提供可以开启、关闭的“自动接受连接申请”功能。

## 已确定的规则

- 页面按浏览器首选语言自动选择中文或英语；不翻译串口 RX/TX 原始数据及设备输出。

- 多个 Remote 可同时获批发送，与 Local 共用一个有界写队列，按 Local 入队顺序依次写入。
- Local 可以暂停全部远端发送，保留远端连接和接收，本机仍可发送；恢复不重放暂停前的旧命令。
- 自动接受默认关闭；开启后可自动批准多个只读和发送端，暂停远端发送时关闭。
- Local TX 日志记录本机/Remote 来源和入队序号，便于分析多端操作与设备输出。
- 弱网时保留设备 RX：Local 使用有界内存缓存（最多 1 MiB、8192 帧、30 秒），按流 ID 和序号向同一 Remote 续传；Remote 重新申请并获批后才允许补传，新 Remote 从当前实时数据开始。接收端以单调递增的累计序号确认并去重；服务器允许确认落后于已发送窗口，但拒绝尚未发送的序号；缓存过期/溢出必须显示缺口。缓存只在当前 Local 串口会话内有效，关闭串口或停止共享即清除。
- 断线、撤销、暂停或重连后绝不自动重放旧 TX 命令；RX 缓存仅用于已授权 Remote 补收设备字节。
- 共享码紧邻共享开关，注册成功后显示并可复制。

界面采用顶部串口与状态、主区日志、右侧连接管理、主区底部发送的布局。

## Remote 界面

Remote 与 Local 使用一致的工作区布局和视觉样式：顶部输入共享码和申请权限，收发日志作为主体，发送区放在主区底部，连接信息及网络参考放在右侧。窄屏时侧栏移到下方。

Remote 串口与 ESP32 工具在同一页面内切换，复用同一个 WebSocket 和当前授权；导航不刷新页面、不重新申请连接。直接打开两个工具路由时也加载相同页面，由当前路由选择显示的工具。

权限选项显示“只读”和“完全控制”。不显示统一排队提示及发送区的解释段落；保留现有授权、暂停、排队和串口参数规则。

完全控制权限包含远程修改五项受支持串口参数，由 Local 实际执行并向所有获批端同步结果；只读端只能查看。一次一个修改，写队列未空时拒绝；修改期间停止新发送，失败尝试回退，超时或实际状态无法确认时停止共享。暂停或撤销能取消后续步骤，已开始的驱动调用不能撤回。详细约束见 [授权模型](ACCESS_CONTROL.md)。

Remote ESP32 烧录使用顶部共享码和已批准的完全控制连接，操作 Local 已打开的物理串口；不访问 Remote 浏览器本机 USB。页面左侧工具导航固定，顶部共享码/连接状态始终可见。烧录会话临时独占串口写入，接收保留；Local 显示占用状态但不增加烧录入口。烧录页只提供 BIN 文件与地址选择，不要求编写或导入 JSON；保留多行文件列表，配色、控件、圆角和日志样式与现有页面一致。

## 定时发送与计数

- Local 和 Remote 的发送区提供定时发送，默认间隔 1000 ms，可设置 20–86400000 ms 的整数；开始时固定本次文本/HEX 和行尾，一次客户端提交完成后再等待下一间隔，不并发提交周期，也不追赶漏过的周期。Remote 的提交完成不等于设备执行完成。
- 定时发送默认关闭，必须显式开始；停止后不再提交后续周期，并作废 Local 尚未进入驱动的定时队列项和远端尚未向服务器提交的直连请求。已经提交 TX 意图的这一条在授权仍有效时完成一次，避免留下已批准但永不送达的写入空位；暂停、撤销、断线等状态变化仍立即作废旧写入，不影响接收通道。发送失败、串口关闭、Remote 失去发送权限或连接、参数修改及烧录独占会停止对应定时发送，不自动恢复。Local 独立定时发送不依赖共享网络。已提交至网络或驱动的在途字节不能撤回。
- 两端提供 RX/TX 字节计数和独立的“清零计数”。HEX、UTF-8 文本、行尾均按实际编码字节计算；Local TX 计实际完成的串口写入，Remote TX 计成功提交的字节，不代表设备执行确认。
- 清零计数不清空日志、发送内容、接收游标或授权，不重置流式文本解码器；清日志也不清零计数。Remote RX 不重复计入已交付过的相同流序号。

## 页面网络参考


Local 与 Remote 页面提供按需触发的网络评估。未直连时评估本页到服务器的下行与 HTTP 往返；已直连时评估当前对端的 P2P 双向有效速率与往返。显示评估路径、对象、探测超时及参考波特率；Local 的多个已授权对端可在原侧栏选择。路径或授权变化后取消进行中的评估并使旧结果失效，不静默切换测量对象。

默认不主动测速、不自动修改串口参数。P2P 探测使用独立有界通道，只读授权也可评估；不写串口、不计串口收发字节，配置、烧录、定时发送和补传等事务期间拒绝探测。浏览器无法测得真实 IP 丢包率，须明确区别探测超时与丢包；参考不能替代完整串口链路和长期稳定性验收。

## P2P 接入约束

- 增加 P2P 时保持 Local、Remote 现有布局、样式和操作流程，不重排共享码、日志、发送区、侧栏或工具导航。
- 传输方式由系统自动协商，优先直连，不能直连时使用中转；不增加用户必须配置的 P2P 开关或协商步骤。
- 仅在现有连接状态位置显示“直连 / 中转”；Local 按远程端分别显示，Remote 显示当前连接。连接失败、操作中断仍须明确提示。
- 保留现有审批、只读/完全控制、暂停、撤销和有界写队列规则；通道切换不得重复执行旧 TX，也不得静默重试烧录。
- P2P 实时 RX 与中转历史补传可以互补，使用同一流和序号排序去重。补传时不在服务器另排现代接收端的实时载荷；有界暂存不足时继续从 Local 缓存请求，缓存不足明确提示缺口，不能用重复 TX 或无界内存换取连续性。

普通串口页面已按以上边界接入直连与回退；原有合成数据实验保留独立入口。当前本机浏览器/Win32 串口验证通过，跨机器、NAT 和浏览器原生串口权限仍需验收；实现和验证边界见 [P2P 实验](P2P_PROBE.md)。

## 公共服务与运营方向

- 首阶段不做用户注册、账号登录，使用工具无需创建账号；共享端仍按既定审批和自动接受规则控制远端权限。
- 多用户使用时控制服务器带宽、连接数和内存占用；采用全局、源会话及 IP 资源预算，按转发副本计算流量，超限明确停止共享并保留本机串口。当前实现与默认值见 [资源限制](RESOURCE_LIMITS.md)。
- 本阶段不接入广告，优先完成现有功能与共享服务资源限制。

预览部署与验收进度见 ROADMAP.md；免账号不改变共享端对串口访问权限的决定。

## Windows 桌面串口客户端（提议）

- 目标：自研 SSCOM 风格的 Windows 客户端，不修改或依赖第三方 SSCOM；客户端与现有 Web Local/Remote 形成同一闭环。
- Local 客户端可打开本机 COM 口；Remote 客户端和 Web Remote 可按同一共享会话申请权限。Local 审批、只读/完全控制、串口参数、统一写队列、RX/TX 字节、日志和断线恢复规则需要跨客户端保持一致。
- 客户端串口调试至少覆盖现有 Web 的文本/HEX 收发、定时发送、RX/TX 计数及记录导出；Web 页面可以看到同一会话状态和来源日志。双向字节须保真，写入继续受 Local 授权、暂停/撤销和有界队列保护；不开放无认证的公网串口端口。
- P2P 优先验证浏览器 WebRTC DataChannel 与原生客户端是否可互通；如果可行，Web 和桌面端共享一套信令与串口数据协议。ZeroTier 1.16.2 核心是另一条原生 P2P 候选：现有本机原型使用自建协调节点做身份查询/会合，A/B 业务数据直发；协调节点不转发业务数据，打洞失败超时。该原型的跨 NAT 结果和协调服务器当前状态均未在本轮重新确认。打洞失败时是否复用现有 WSS 中转仍待确定，不能自动套用该原型的直连失败策略。
- ZeroTier 等私有覆盖网络可作为可选网络路径，不是串口协议转换或 ShareSerial 授权的替代品。技术方案待定：可比较 Rust 与 Windows MFC，确定客户端运行位置、物理串口归属、会话桥接、打包与更新边界。仅 COM 的第三方程序适配（如虚拟 COM 端口）另行评估，不作为首阶段前提。
- 若复用 ZeroTier 核心或原生 WebRTC 库，保留其许可证及各第三方组件声明，发布包不能只标主项目的 MIT 许可；按目标平台记录编译工具链和系统库依赖。
- 状态：待设计与原型验证；当前只有 Web Local/Remote 和 Windows 服务 EXE，没有独立桌面串口客户端。
