# 正向、负向与变异测试

正向测试证明正常行为可以完成；负向测试证明非法输入或状态被拒绝；变异测试验证已有断言能发现故意植入的错误。三者不能互相替代，竞态检查也不是变异测试。

## 当前方案

使用 Node.js 标准库运行定向变异，不引入 npm 或 Go 运行依赖。清单在 [manifest.json](../tests/mutation/manifest.json)，执行器在 [mutation-test.cjs](../scripts/mutation-test.cjs)。

当前清单包含 293 个针对核心行为手工选择的变异。在收发、授权、多发送端、资源预算、Local 独立调试和网络参考边界之外，包含 31 项远程参数修改、13 项 RX 补传、5 项 ESP32 固件清单、4 项手动地址及异步确认、4 项远程烧录会话、7 项烧录准备/重试/进度/完成状态、9 项合成 P2P 实验授权/代次/端口/迟到事件/积压变异、15 项真实串口 P2P 授权与补传边界、6 项 STUN 配置/诊断边界、1 项串口 ICE 过早截止、4 项失败快照校验、报告者身份、授权失效和采集期限变异，以及 8 项重试轮次、发起者、次数、总窗口与退避边界变异。数量表示清单范围；是否检出以对应源码指纹的完成报告为准。

另有 6 项覆盖 RX 双路径协同：补传期间的实时数据队列、后续游标、直连尾部暂存、历史 ACK 边界和 Local 并行直连发送。

新增 9 项覆盖定时发送的单次在途、停止/权限/授权绑定、排队写入和异步摘要取消、发送积压，以及字节计数与清零不回退接收游标；另有 3 项覆盖旧 P2P 错误的关联信息和两端过期提示隔离。原有变异保留，仅随函数调整更新等价边界的替换锚点。

另加 3 项覆盖过期写许可的立即丢弃、Local 写入代次变化的 TX 清理，以及取消期间异步摘要完成后不得写入。停止定时的取消边界明确为 TX 意图提交之前；已提交且仍获授权的单条请求完成一次，不留下 FIFO 空位，现有取消变异继续覆盖提交前的边界。

另有 2 项区分补传的有效游标进展和无进展通知：慢速持续推进应续期 30 秒空闲提示，重复的无进展不能延后提示。接收缓存、队列容量和授权规则不变。

另加 12 项覆盖当前路径的网络参考：服务器/P2P 选择、结果作用域及二进制开销模型、授权和忙状态、探测总字节/帧/消息/时间上限、页面互斥及冷却、串口通道隔离和过期结果清理。旧变异全部保留。

另加 1 项覆盖探测接收端的直连确认通知迟到：发起端已确认、授权及主通道有效时，独立网络探测不能依赖接收端 UI 状态通知同时到达。串口发送仍须原服务器许可。

另加 5 项覆盖故障诊断：RTC 错误类型/SCTP 数字码、关闭测速前冻结上下文、旧轮次报告隔离、服务端上下文字段白名单/范围校验及每端每轮日志去重。原有检出点全部保留；首次回退原因仍为权威状态，另一端仅补充证据。

另加 7 项覆盖 P2P TX 队列拆分路由：双方能力协商、Local 发起身份、服务端停止签发直连 TX 许可、保留 RX 直连、取消且不重放在途 TX、完整回退后状态清理，以及 Remote 后续 TX 走 WSS。

另加 10 项覆盖持续监控恢复：Local 自动接受偏好默认关闭、存储/清除规则，Remote 目标与权限保存、新授权请求、在审批中切换设置、异常断线及 Local 离线重试、拒绝/手动断开停止重试。

另加 6 项覆盖系统日志与串口日志隔离：Local 连接事件不进入 RX/TX 终端，系统日志导出来源正确，清空串口历史保留诊断；Remote 事件单独存放、有界保留，清空 RX 不清除系统日志。

另加 3 项覆盖 Remote 单页工具导航：工具切换保留当前 WebSocket 与授权；ESP32 面板复用同一 Remote 会话；/remote 与 /remote/esp32 由同一 HTML 页面提供。

这是可审查的定向变异清单，**不是穷举 AST 变异，也不提供全项目的缺陷发现率**。清单内达到 100% 只能证明这些指定错误被当前测试检出。

ESP32 页面已移除 JSON 清单导入，只保留 BIN 和地址选择。底层结构/范围/摘要校验仍用于内部生成的镜像布局，原有核心变异与边界测试继续保留；旧导入界面的用例改为 BIN 替换、取消勾选与断线后丢弃迟到哈希结果的回归。

隔离输入还包括 Windows 原生入口、共用证书生成代码，以及发布包测试使用的项目许可证和第三方声明。未复制必需测试输入时基线会失败，必须修复隔离清单后重跑，不能计为变异检出。

第一轮 46 项清单从 29/46 提升至 46/46 的历史记录见 [结果记录](MUTATION_RESULTS.md)。当前授权轮次使用扩展清单，需以新报告的范围和源码指纹为准。

授权轮次最终 74/74 项检出，详见 [授权验证记录](ACCESS_VALIDATION.md)。

## 运行

需要 Go 1.25+ 与 Node.js 24，依赖仍按 go.mod/go.sum 获取。

```sh
node --test tests/mutation-runner.test.cjs
node scripts/mutation-test.cjs
```

本机系统 Go 过旧时可明确选择工具链，例如 PowerShell：

```powershell
node scripts/mutation-test.cjs --go .local/tools/go1.25.14/go/bin/go.exe
```

--go 应使用绝对路径，或命令可从 PATH 直接解析；相对路径按启动目录解析。也可通过 MUTATION_GO 指定工具路径。

```sh
node scripts/mutation-test.cjs --only js-hex-odd-length
node scripts/mutation-test.cjs --report-dir .local/mutation-review
```

默认报告在 .local/mutation-report/report.md 和 report.json，另有每个变异的原始输出日志。--only 的报告明确标记选择数量，不能将局部运行的得分当作全清单得分。

## 执行与判定

1. 只复制源码、go.mod/go.sum 和测试到独立临时目录，不复制 .git、证书、私钥、产物或 .local。
2. 在未变异副本上运行完整 Go 测试与前端产品测试，基线失败立即停止，不生成有效变异得分。
3. 确认每个替换锚点唯一且变异确实改变代码，然后一次只应用一个变异。
4. JavaScript 先检查语法，再运行产品测试；Go 根据 test -json 的真实测试事件判断。
5. 每个变异后恢复副本中的原文件。结束时核对原工作树输入哈希，删除经过路径校验的临时目录。

| 状态 | 判定 | 得分处理 |
|---|---|---|
| killed | 可运行的变异使至少一个测试明确失败 | 计为检出 |
| survived | 测试实际执行并全部通过 | 计为未检出，阻止门禁通过 |
| invalid | Go 编译/vet 失败或 JS 语法错误 | 不算检出，运行不合格 |
| timeout | 测试内部或进程超时 | 不算检出，需人工检查 |
| error | 启动失败、报告不可解析或没有明确测试结果 | 不算检出，需修复环境/执行器 |

得分 = killed / (killed + survived)。所有选择的变异都必须是 killed，且基线、完整性与清理均成功，命令才退出 0。INVALID/TIMEOUT/ERROR 即使被排除在得分分母外，也会使门禁失败。

Go 使用 -count=1 禁用测试结果缓存，保留正常编译缓存；每个包测试超时 15 秒，每个外部进程默认超时 90 秒（基线 300 秒）。超时会终止本轮子进程树。

执行器自身的分类与目录清理测试单独运行，不加入产品变异的检出统计，以免通过“源文件被改动”这种断言虚增检出率。

## 维护规则

- 新增重要边界先补正/负用例，再添加可以检验这些断言的变异。
- 变异存活时先查看实际行为和断言缺口，不通过删变异或放宽门禁来提高分数。
- 源码重构使锚点失配时更新清单并审查变异含义，不能静默跳过。
- 确认为等价变异时应记录理由并用非等价的行为变异替换，不能把等价或无效变异算作 killed。
- 报告包含源码/测试哈希、工具版本、失败测试名称和日志。比较得分时同时检查清单范围与输入哈希。
- 真实设备、浏览器权限、心跳时间行为、物理写入 ACK 等未被此清单覆盖的能力仍需各自的测试与验收。

GitHub Actions 在独立 Linux job 中执行全清单，并上传成功或失败报告。Gitee 镜像不执行 GitHub workflow。
