## Windows 串口与 WebSocket API 实机验证（2026-10-17）

使用真实 COM5/COM6（Windows usbser、TinyUSB CDC），先直接调用 Win32 SetCommState/GetCommState/ReadFile/WriteFile。COM6 保持 115200：COM5 同为 115200 时双向测试载荷逐字节一致；改为 19200 或 9600 时，驱动读回设置成功但接收字节不匹配；恢复 115200 后重新一致。由此确认这组设备的速率设置会影响实际传输，不能用虚拟串口忽略波特率解释。测试后恢复两端原有 115200/8N1 配置及控制标志，并释放端口。

随后在 Node 中执行生产 Local/Remote JavaScript，使用 DOM 测试壳与 Win32 支持的串口适配器，经实际本机及公网 WSS 完成审批、115200→19200→115200、参数确认与事件，再核对 COM6→Remote 及 Remote→COM6 的已知载荷。本机与公网最终复测均进程退出 0：同速 106/106 字节一致，19200/115200 的 104 字节输入仅收 17 字节且不一致，恢复后再次 106/106 一致；Remote 发送至真实 COM6 为 39/39 一致。公网该次两次参数确认分别约 620/1091 ms，Remote 到驱动 write 完成约 139 ms。这是少量 ASCII/CRLF 测试，不是带宽或持续压力验收。

原始结果保存在忽略目录的 serial-api-hardware-result.json、serial-api-product-local-result.json、serial-api-product-hardware-result.json。早期 API 测试壳缺少 select 自动选中行为，已显式设置选中项；另有公网恢复或发送等待超时，失败尝试另行保留，不能被最后一次成功覆盖，也未据此认定网络故障根因。此轮未启动 Chrome；浏览器原生 Web Serial 实现、权限对话框、其他四项硬件参数及失败回退仍需独立验证。

## 本轮行为

- 所有 Remote 在读取串口数据、查询端口详情或发送数据前都需 Local 批准。
- 默认只读，同一 Local 同时最多一个控制端；Local 可降为只读、拒绝和撤销。
- 批准/拒绝/撤销绑定实际共享端连接；申请 ID 为 128 位随机数，60 秒过期，不继承断线前授权。
- 每 Local 最多 8 个待批准申请和 16 个已授权 Remote；没有跨连接/IP 限流或全局连接上限。
- Local 核对自己的批准选择，在消息入队和实际写入前检查权限；点击撤销后立即停止尚未执行的写入。
- 已交给串口驱动的在途写入无法撤回；物理写入 ACK 与错误回传尚未实现。

## 浏览器验证

真实无头 Chromium、实际 HTTPS/WSS 服务、页面按钮、浏览器 ReadableStream 与模拟串口写入接口完成以下流程：

1. Local 选择/打开模拟串口并完成 v2 注册。
2. Remote 申请只读，Local 批准；能收到数据，不能发送。
3. Remote 申请控制，Local 批准；41 00 FF 加 CR 的原始字节保真，并向只读端同步接收。
4. 第二个控制申请获批时返回占用错误，保持等待。
5. Local 撤销原控制端后批准新控制端，完成控制权转移。
6. Local 拒绝读申请，Remote 回到可重新申请状态。
7. Local 关闭串口，所有获批 Remote 复位。

浏览器测试使用模拟物理串口，未操作真实硬件。开发证书错误仅在独立测试浏览器进程内忽略，没有修改系统或用户浏览器信任设置。界面截图保存在 .local/access-local.png。

## 2026-10-21 本机 RX 压力复测

使用绑定 `127.0.0.1:12446` 的当前 Go Hub、生产 Local/Remote JavaScript、Node DOM 测试壳和 Win32 COM5/COM6 适配器；串口均为 115200/8N1，TLS 校验本机证书，未使用 Chrome 原生 Web Serial。COM5/COM6 经串口线回环，三个阶段均使用全字节范围的确定性二进制载荷：

| 场景 | COM6 发送 / Local 接收 | Remote 接收 | 结果 |
|---|---:|---:|---|
| Local WebSocket 断开期间缓存并补传 | 262144 / 262144 字节，22.816 秒 | 262144 字节，1543 帧；补传 5.232 秒 | 字节完全一致 |
| 正常连接实时 RX | 65536 / 65536 字节，5.755 秒 | 65536 字节，385 帧 | 字节完全一致 |
| 断线期间持续接收，超过 30 秒缓存期限 | 524288 / 524288 字节，45.645 秒 | 缓存保留并补回 343908 字节，2028 帧；明确报告序号 1929–2997 缺口 | 保留尾部与原始输入逐字节一致 |

串口输入实测约 11.4 KiB/s；受限速保护后的补传约 50 KiB/s。此前未限速的回放曾触发 `bandwidth_limited` 并关闭共享；Local 补传增加 128 KiB/s、32 KiB 突发的应用字节限速后，完整重跑通过。压力数据还表明 256 帧上限在该驱动的小块读取下只能保留约 42 KiB，因此缓存帧数提高到 8192；1 MiB 字节上限和 30 秒期限仍有效。Hub 的累计 ACK 校验也调整为接受已发送窗口内的单调确认，同时继续拒绝尚未发送的序号。

测试结束后 COM5/COM6 均恢复 115200/8N1 并释放；Local/Remote 与串口桥接进程正常退出，临时本机 Hub 随后停止。完整报告在忽略目录 `.local/deployment/serial-api-rx-pressure-local-result.json`。这是本机回环与本机 Hub 压测，不代表公网限速/丢包注入，也没有验证 Chrome 原生 Web Serial 权限；公网带宽受限测试随后执行。
