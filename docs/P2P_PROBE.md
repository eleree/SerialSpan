# P2P 本机实验

分支 `experiment/webrtc-p2p`，版本 `0.1.0-beta.2-p2p.1`。独立入口 `/experimental/p2p` 只传合成二进制数据，不选择、读写物理串口，也不烧录 ESP32。2026-10-28 已另将直连接入普通 Local/Remote 串口页面，见下文“普通串口接入”；ESP32 烧录仍使用中转。

## 使用

1. 启动本分支服务，打开实验页，角色选 Local，点击“开启实验”。
2. 用另一个页面或浏览器上下文打开同一地址，角色选 Remote，输入共享码。默认申请只读；需要测试 Remote 发送时选择完全控制。
3. Local 核对远端编号后批准。批准前不创建 PeerConnection 或转发协商信息。
4. 显示 `p2p` 后，选择目标和测试大小，发送并核对 SHA-256。Local 可以向只读端发送；Remote 发送必须已获完全控制。
5. 直连失败或主动关闭后变为 `websocket`，当前测试中止，不自动重发旧数据；手动开始新的中继测试。

配置 `iceServers: []`，本机测试不需要 STUN/TURN，不接入第三方服务。跨机器防火墙、NAT、公网穿透和 Web Serial 权限需要分别验收。

## 实现边界

- 复用 v3 的共享码、手动审批、只读/控制、暂停、撤销及断线清理。共享码是定位符，不是密码。
- 只有双方声明 `p2pProbeProtocol=1`、端口为 `p2p-probe` 的合成端可以协商；不能与普通物理串口页面混用。
- Go Hub 依实际 Socket、Local/Remote、port 和 grant 转发 SDP/ICE/回执，拒绝待批准、过期授权、错误 Local 和错误端口。保留现有同源、心跳、大小、队列和资源限制。
- DataChannel 可靠、有序；单帧最多 16 KiB，积压上限 64 KiB，ICE/待处理信令有界。每 Peer 每方向最多一项测试，每项至多 4 MiB。
- 合成接收端复核授权、暂停和写入代次，按 ID/偏移/长度接收，完整后核对 SHA-256；撤销、断线或切换后，迟到事件不恢复旧测试。
- 控制信令断开会关闭直连；没有离线授权继承。回执是元数据，允许只读端回复。
- 直连合成数据不经过 Go 字节预算或物理串口路由；WSS 合成兜底逐帧检查控制权限、暂停和代次。此实验不是公网计费或安全审计方案。

以上限制针对合成测试页。普通串口接入使用下文的逐条摘要许可和原 RX 补传路径，不使用合成帧绕过物理串口授权。烧录不会由本实验自动续传。

## 普通串口接入（2026-10-28）

### TX 队列触顶时保留 RX 直连（2026-11-03）

当 Local 收到的直连 TX 许可与数据暂时无法配对，待处理项达到 16 个时，双方都支持 `serialP2PTXRelayProtocol:1` 的会话只切换该 Remote 的 TX 到现有 WSS 写队列，当前有序 DataChannel 继续传输 RX。服务端按 Remote 记录该模式，并拒绝新的 P2P TX 许可；其他获批端仍独立协商和收发。两端丢弃未完成 TX，不自动重放；用户需检查设备状态后再决定是否重发。旧页面保持整条连接回退。

开发验证使用原生 WebRTC DataChannel 和模拟 Web Serial：人为丢弃直连 TX 帧直至触发 16 项上限，确认 Local/Remote 的 P2P Link 仍打开、旧 TX 未重放、后续 `00 FF` 经 WSS 到达串口写入器一次、Local RX `[07 08 00 FF]` 仍经 P2P 到达。拆分路由下网络参考选择服务器路径，避免把只用于 RX 的直连误报成双向 TX 直连。该验证不覆盖实体设备和跨机器公网长期稳定性。

### 有界后台重试（2026-10-28）

普通 Local/Remote 通过额外的 `serialP2PRetryProtocol:1` 协商重试能力，现有 HTML/CSS 和操作入口保持不变。每轮最多 45 秒；网络类失败后由 Remote 在 5/10/20 秒退避后请求下一轮，最多 4 轮，批准后的总窗口为 180 秒。等待和重新协商期间继续中转收发。服务端校验实际授权、轮次、次数、时间及失败类别，再同时通知两端新建 PeerConnection；旧端保持单轮行为。

重试保留 grant、写入代次、TX 单调序号和 RX 游标；只重试建连，不重发串口命令。旧轮次信令/许可、通道及迟到异步操作不能恢复旧发送或结束新协商；授权结束清理计时器。协议/字节校验失败和已报告的 DTLS 失败不触发自动重试。系统日志导出与悬停诊断可查看尝试轮数，服务器记录 `serial_p2p_retry`。详细消息见 [协议](../PROTOCOL.md#串口-p2p-扩展)。

### RX 双路径协同（2026-10-29，开发验证）

真实使用反馈中的 `send_queue_limited` 在获批约 5 秒后出现，断开时 WebSocket 发送队列仅为 162/810 B。代码中另一个同码分支为补传期间的实时 RX 等待队列：最多 256 帧/192 KiB，连续设备输出可能在 ICE 完成前触发此保护。

现代串口 P2P 接收端在补传时不再使用该第二份服务器实时载荷队列，而由现有 Local 有界缓存保留字节、服务器同步最新 head。P2P 实时尾部和 WSS 历史补传同时进行，接收端暂存未来序号，历史范围完成后按序合并；暂存溢出则继续分段请求 Local 缓存。只补收 RX，不重发 TX，缓存无法覆盖时仍明确显示缺口，旧端和实际 WebSocket 发送队列继续保留资源上限。

Go 格式/vet/测试、161 项 Node、Linux 隔离源码 race 及完整 232/232 项变异检查通过。新增回归覆盖超过原 256 帧等待量而保留授权、普通/直连数据入口、最新 head、直连尾部合并、无提前历史 ACK 及暂存溢出后的下一窗口。报告保留在维护机 `.local/mutation-hybrid-rx/`、`hybrid-all-node.log`、`hybrid-race.log`。本阶段尚未部署；新浏览器协同流程、持续流量和真实硬件仍待分别验证。

### 查看为什么回退中转

将鼠标放在 Remote 顶部“中转”或 Local 对应远程端的连接文字上，可查看最近诊断；需要完整阶段与原因时，从页面导出系统日志。开发者控制台运行 `await getConnectionDiagnostics()` 可读取结构化快照。诊断只含状态、类型计数与统计，不导出 SDP、候选 IP、授权令牌或原始错误文本。

浏览器关闭 PeerConnection 后可能清空候选对/传输统计；只保留 `connection_failed` 与候选数量不足以区分 ICE 路径和 DTLS。普通串口现在先切回 WSS，再在 200 ms 内尝试一次有界统计采集，记录原始失败时的 ICE/DTLS/SCTP 状态及请求、响应、成功候选对计数，服务器自动记录 `serial_p2p_failure_details`。授权失效立即关闭，迟到采集不发送也不显示；统计不可用时不把零计数当作无回包证据。取得回包和成功候选对后仍须结合 DTLS 状态判断，不能单凭 `srflx` 或状态名称确定 NAT 类型。

## 追加压力与速率（2026-10-27）

Chrome `156.0.8078.48` 与 Edge `156.0.4314.42` 分开运行完整压力流程，避免两个浏览器测试同时争用 CPU。每种浏览器各自使用真实 WebRTC 的独立上下文；没有测试 Chrome 与 Edge 彼此互联。

两种浏览器均通过：

- 5 轮双向并发，每轮每方向 4 MiB，全部 SHA-256 一致。
- Local 同时向两个获批端发送，另一个控制端同时反向发送，共 3 路、12 MiB，全部核对一致；大数据直连阶段 WSS 测试数据帧为 0。
- 同一 Remote 页面连续 10 轮断开、重新申请与批准，包含在途撤销、在途关闭真实 WSS；旧测试中止且没有自动转发旧数据，另一个已批准 Peer 保留。
- WebRTC 不可用时的中继回退，以及既有的只读注入、旧代次、暂停保留接收、原生 DataChannel 中断和撤销检查。

每种浏览器的压力部分核对 53.25 MiB 有效载荷，不包含故意中断的数据和基础冒烟流量。原始数据在维护机器的 `.local/p2p-stress-chrome-final.json` 与 `.local/p2p-stress-edge-final.json`，不提交浏览器临时配置或实际设备日志。

速率单位 **MiB/s**，1 MiB = 1,048,576 B。表内是“中位数（最小–最大）”，每行 5 个样本；这是每方向 4 MiB 的双向并发测试，不是单独单向测试。

| 浏览器 | Local → Remote | Remote → Local | 双向总吞吐 |
|---|---:|---:|---:|
| Chrome | 4.655（4.261–4.831） | 4.752（3.890–4.908） | 7.041（6.133–7.407） |
| Edge | 4.768（4.450–4.883） | 4.755（3.385–4.899） | 7.289（5.574–7.347） |

三路并发的总吞吐为 Chrome 7.303、Edge 6.439 MiB/s，各一轮。

每方向速率使用合成有效字节数除以应用测试耗时，包含 SHA-256、发送和完成回执，不含模式数据生成。总吞吐按整轮有效字节数除以真实壁钟时间，额外包含准备与 CDP 调度开销；没有简单相加两个方向的速率。64 KiB 缓冲与 10 ms 回压轮询也会影响结果。这些数值不是网卡极限、UDP 线速、公网带宽或可承诺的串口波特率。
